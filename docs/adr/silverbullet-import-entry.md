# SilverBullet import launched without an upload batch

Status. Fix applied and navigation verified in the migrated GrupoAuditor VM on 2026-11-11. Upstream changes remain on the local fix/silverbullet-import-entry branch without a commit or publication.

## Failure and cause

Apps → Extensions rendered the generic Run/Retry control for ext-silverbullet-import. That control enqueued the workflow without parameters. Its prepare step requires BATCH, a UUID generated by the document-upload picker, and correctly failed before importing anything. The observed run was 034vVqqAYkfVgClH5Lbsq9 with BATCH empty and error BATCH is not set.

## Correction

The framework panel routes this built-in upload workflow to the existing SilverBullet Knowledge page through an Import documents link. It explains that documents must be uploaded and selected first. Other extension workflow controls retain their previous behavior. The workflow's validation and historical failure remain available.

## Verification and limits

The panel TypeScript and production build passed locally and in the VM. The VM doctor passed. Browser verification confirmed that the replacement link reaches the Knowledge page with its existing upload instructions and Import with AI control. Clicking the replacement link did not initiate another empty import. An actual document import was not exercised. The VM Codex executable was already unavailable, so successful processing with that provider is still unverified.

The rendered framework patch is applied in GrupoAuditor. Publishing and distributing the upstream correction remain pending.

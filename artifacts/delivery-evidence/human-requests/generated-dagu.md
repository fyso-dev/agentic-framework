# Generated-project Dagu test

On 2026-11-14 UTC a disposable project was generated with Copier 9.19.1 and the bundled extension installed from its generated source. The project's own `framework/scripts/run-dagu.sh` started Dagu 2.24.0. With a fictional request and `origin=none`, unauthenticated API access returned 401, the response was saved, and `ask`, `record` and `deliver` succeeded with the expected outputs. The test did not invoke mise or change its trust configuration.

The macOS fixture used the inherited `HOME`, temporary XDG and data paths, explicit tool paths and a sandbox that restricts writes, executable paths and network ports. A supervisor checked listener ownership before API calls and cleaned the dedicated process group. Separate canaries checked blocked writes and connections, process and descriptor containment, and the exact Unix socket exception. The profile allows broad filesystem reads; the test uses fictional data and is not proof of general confidentiality. A Dagu Unix socket under the system temporary directory is allowed by exact calculated name after an absence check; Dagu removes the path before binding, leaving a race and possible collision described in the [proposal](../../../docs/human-requests-proposal.md). Cleanup does not prove containment of a descendant that creates a new session.

This test uses only the request workflow and excludes other scheduled workflows. It does **not** prove `mise run up`, `mise run doctor`, the full generated stack, gateway/browser operation, OpenMausBot continuation, an external HTTP receiver, or cross-platform operation. The independent [assembled-fixture gate](integrated-gate.md) covers a different bot/browser path and must not be conflated with this test.

Reproduce only on macOS with a fresh empty fixture and pinned tools. Set `FYSO_SANDBOX_FIXTURE`, `FYSO_TEST_TEMPLATE_ROOT`, `FYSO_TEST_COPIER`, `FYSO_TEST_COPIER_PYTHON`, `FYSO_TEST_DAGU` and `FYSO_TEST_NODE`, then execute `tests/human-requests-sandbox-supervisor.py` with a compatible Python interpreter. The supervisor applies `tests/human-requests-sandbox.sb`; `tests/human-requests-sandbox-canary.py` exercises its safeguards. The system may deny applying a nested sandbox. Review the profile and its stated limits before use.
